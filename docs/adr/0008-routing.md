# ADR-0008：路由分诊 —— 用「坐席」隔离口径，而不是堆提示词

- 状态：已采纳
- 日期：2026-10-26
- 关联：ADR-0006（四个扩展缝）、ADR-0007（MCP 与 Skills）

## 背景

Skills 上线后仍有一个解决不了的问题：**口径串味**。

一个系统提示里同时装着售前（价格/活动/选型）和售后（退换/赔付/工单）两套规则时，
7B 模型分不清边界。典型错法：

- 拿促销话术回答退换货；
- 拿售后赔付政策回答「这个沙发能不能便宜点」；
- 用户只是打招呼，却被当成技术人员追问「什么型号、报什么错」。

根因不是提示词写得不够长，而是**两种业务共享一份工具权限**。Skill 只加约束、
不删工具——它管不住「谁可以调 create_ticket」这件事。

同时，工具从 3 个涨到 5 个（含 MCP），再涨下去「一次给模型看全部工具」
本身就会拉低选择准确率。

## 决策

### 1. Skill 与 SubAgent 分工：一个管话题，一个管身份

| | 职责 | 是否限制工具 |
|---|---|---|
| Skill | 话题增强：命中后补一段领域指令、把相关工具排前面 | 否 |
| SubAgent | 身份隔离：决定谁在说话 + 工具白名单 | 是 |

两者叠加：SubAgent 划边界，Skill 补细节。一个 SubAgent 生效，同时最多一个 Skill 生效。

四个内置坐席：

| 坐席 | 工具白名单 |
|---|---|
| presale 售前 | `kb_search`、`coupon_status` |
| aftersale 售后 | `kb_search`、`query_order`、`create_ticket`、`logistics_track` |
| tech 技术支持 | `kb_search`、`create_ticket` |
| general 兜底 | 不限（空 = 全量） |

兜底坐席刻意不限工具：**分不清的时候宁可给全量，也不要把用户卡死**。

### 2. 路由做成规划器的装饰器，不做新的一层循环

`AgentPlanner` 是 Protocol，`PlannerDecision` 只有两种。所以 `RouterPlanner`
可以包在 LLM 规划器外面：收窄 ctx（换掉 tools、挂上坐席指令）→ 委托 → 返回同一种决策。
`runtime.py` 只加了一段权限校验，事件循环本身没动。

### 3. 三层判定，按「便宜到贵」排列

1. **规则**：触发词打分 + 单号正则（`CS\d+` / `SF\d{8,}`）。长词优先、命中即遮盖，
   避免「退款」和「要退」在同一句里被算两分。明确命中就直接定，**零模型调用、零额外延迟**。
2. **沿用**：本轮没有任何信号、但同一会话上一轮有坐席 → 沿用。
   接住「那什么时候到」这种不带关键词的追问。**兜底坐席不参与沿用**——
   上一轮是「你好」不代表这一轮也该模糊处理。
3. **模型**：规则并列或完全无信号时，调一次 7B 分类（`temperature=0`、`max_tokens=32`、
   4 秒超时）。失败退回最高分或兜底。

绝大多数请求（问价格、问退款、给单号）走第 1 层，额外开销为 0。

### 4. 隔离做两道，不只做一道

- **可见性**：`ctx.tools` 只保留白名单内的工具，模型看不到越权工具；
- **执行侧**：`ToolCallDecision.allowed_tools` 随决策带回，runtime 在执行前再校验一次。

只做第一道不够——模型可能吐出一个清单外的工具名（幻觉或提示词注入），
而 `registry.get()` 是全局的，会真的执行。

### 5. 归因写进 done 帧

`RunMeta` 增加 `agent` / `route`（rule·carry·llm·fallback·confirm）/ `handoffs`。
确认轮不经过规划器，由 runtime 通过 `agent_resolver` 从 router 补最后服务过的坐席——
否则 done 帧会莫名其妙地丢 agent，线上无法按坐席统计。

## 后果

**收益**

- 售前/售后口径不再互串；每个坐席的工具集是硬边界。
- 工具总数增长不再线性拉低选择准确率（每个坐席只看到 2~4 个）。
- 分诊结果可观测：`/api/agents` 看配置，done 帧看实际路由。

**代价**

- 模型分诊时 +1 次调用（约 0.6~1.2s）。靠规则优先把这个概率压到很低。
- 坐席切换会丢上下文——多轮里用户可能要说两遍。缓解：沿用策略 + memory 是共享的。
- 新增一层配置：加坐席要改 `subagents.py` 的触发词与白名单，两处必须同时维护。

**降级行为**

LLM 不可用时规划器降级到 `RulePlanner`，此时路由被绕过、白名单失效。
这是刻意的取舍：**可用性优先于隔离**。规则规划器的工具选择是硬编码规则、
不接受模型输出，所以这条路径上的权限风险可控。

## 过程中修掉的真问题（都不是路由本身，但都因路由暴露）

1. **分诊目录漏了 general** → 模型只能在业务坐席里硬选，「你好」被判成技术支持，
   一开口就被问「什么型号」。修：坐席目录必须包含兜底项。
2. **降级路径把写给模型的指令念给用户** → `RulePlanner` 直接把 observation 当回复，
   用户看到「知识库查询失败。请如实告知用户稍后再试，不要编造答案。」
   修：`sanitize.user_safe_echo()` 摘掉指令行。
3. **分块丢标题**（`packages/kb-core/src/kb.ts`）→ markdown 按标题切段后正文只剩
   「- 价格：2999 元」，主语留在 `headingPath` 里。结果「三人位多少钱」**0 命中**，
   「双人位有什么颜色」答成单椅的颜色。修：入库时把标题拼进 chunk 正文。
   修前 rerank 0 命中 / 修后 0.907。
4. **知识库文档不能跨段引用** → 示例文档写「材质与颜色同三人位」，片段里没有颜色名，
   检索无从命中。这是文档写法问题，不是代码问题，但值得写进入库规范。
5. **本地调试要绕过环境代理** → 环境里的 `HTTP_PROXY` 会同时劫持 openai SDK 和
   本地 curl，表现为随机的 `Connection error` 与 `Request timed out`。
   服务启动时用 `env -u HTTP_PROXY ...`，curl 加 `--noproxy '*'`。

## 否决的备选

- **一个 Agent + 更长的系统提示**：试过了，口径串味不是长度问题。
- **每个坐席一个独立 AgentRuntime 实例**：memory、会话、SSE 都要复制一份，
  且跨坐席多轮会丢上下文。
- **用向量相似度做分诊**：需要额外维护坐席描述向量，且对「帮我建个工单」这类
  短指令不如关键词稳。规则 + 一次小模型分类已经够用。
