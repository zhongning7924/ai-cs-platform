# ADR-0012：公众号渠道 + 管理后台（把「引擎」补成「产品」）

状态：已采纳
日期：2026-10-29

## 背景

对标外部「AI 知识库客服」产品时发现：我们的引擎（多坐席路由 / RAG / 转人工 / 反馈闭环）
比它强一档，但缺两块「门面」——**没有公众号/服务号渠道**（靶客户全在微信生态），**没有可视化管理后台**（提示词 / 模型 / 咨询记录都要改代码或看文件）。

本 ADR 记录补齐这两块时的关键决策。

## 决策

### D1：公众号用「被动回执 + 异步客服消息」，不用同步被动回复

微信要求被动回复 5 秒内返回，而 LLM + 工具调用 3~8 秒，硬同步必然超时导致微信重试刷屏。
所以：收到消息先回「已收到」（毫秒级），真正答案异步调智能体 → 客服消息接口（48 小时内可发）推回。

### D2：openid 直接当 session_id

不另造公众号会话映射。这样公众号里的多轮咨询、转人工工单、反馈数据，
与网页挂件共用同一套链路，不需要第二套状态。

### D3：persona 与护栏硬规则分成两段，护栏永远追加

后台能改的是「人设」（品牌/语气/业务范围）；防幻觉、防工具调用泄漏等硬规则
由代码追加在最后，**不可被后台覆盖**。否则后台一次配置错误就能让模型编数据、
把工具调用写成文字发给客户。persona 逐请求透传（PlannerOverrides），实时生效。

### D4：模型生成参数实时热改，base_url/key 保持部署级

model / temperature / maxTokens 是 `create()` 的调用参数，改它们无需重连 client，
因此随请求透传、后台改完立即生效。base_url / api_key 属安全边界，留在 `.env`，
不进后台——改错了会打到别人的模型端点。

### D5：知识库初始化失败必须降级，不能崩溃

真机验证时 Qdrant Cloud 抖动导致 `ensure_collection` 抛异常，整个服务起不来。
修成 try/except：连不上就「不注册 kb_search」，服务降级为无知识库模式继续跑。
这一条对私有化内网、网络抖动、客户漏配，就是「还能用」和「起不来」的分界线。

### D6：公众号路由无论是否配置都挂载

若只在配置齐全时才挂 `/wechat`，未配置时请求会落到静态 catch-all 返回 200，
微信的服务器验证会把「没配好」误判成「验证成功」。改为始终挂载，未配置时
返回明确的 500 提示。

## 后果

- 管理后台 `/admin`（单文件零构建）可维护：客服人设、模型参数、咨询记录、运行状态。
- 公众号 `/wechat`：明文模式下开箱可接，需配 WECHAT_TOKEN / APPID / SECRET。
- 已知限制：公众号仅明文模式（AES 加密模式未做）；异步客服消息失败仅记日志不回退；
  知识库在线入库仍是 CLI（未进后台）；模型运行时覆盖只影响 LLM 生成参数，不影响 embedding/rerank。
